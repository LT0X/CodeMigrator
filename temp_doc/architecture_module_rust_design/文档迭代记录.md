## D-040 · 2026-08-23 依赖地图与并发量级对齐：完备性对抗审计 + 三池模型

本节记录对 Anthropic 迁移博客/kit 的三方交叉核查（claude.com 博客、starter kit 原始提示词、Jarred 本人博客）与两项架构决策。事实核查结论：kit 提示词是"重构的通用化模板，非实录"；Bun 实际路径为手工 crate 预拆分 + agent 分类循环依赖归属 + cargo check 当裁判（~16,000 错误）+ Phase D 64 路并发修复（16 循环×4 worktree，每循环 1 实现+2 对抗评审+1 应用）；LIFETIMES.tsv 的"提案→双对抗评审→序列化成表→供其他 claudes 消费"模式与本库 MigrationRulebook 受控追加同构。完整核查与清单见 [align_records 第 10 节](../feedback_doc/align_records.md)。

- **完备性对抗审计入 M-06**：机械层产出后、CreateRun 签核前执行一轮——双怀疑派评审（独立上下文、不相交抽样[随机半+对抗指派半]）、file:line 证据行双向 diff（漏判/多判）、确认差异=修提取规则不修结果、重生成换样重抽、三轮失败升级用户决策；审计记录随计划证据归档。运营流程零新机制；
- **三池模型**（资源公式升格，M-00/M-09）：`min(4,…)` 改判为**同时活跃 bwrap 沙箱执行位**上限——Shell/Scaffold/一次性检查按需取用、用毕归还，长驻卷与缓存保留；模型会话池解耦——只读工具与模型调用不经沙箱，Slice 会话并发由 provider 配额与 Run 预算约束，可支撑数十路扇出；裁决派发池维持 active-attempt gate。安全性不减（bwrap 只罩不可信执行），解锁博客量级的会话扇出；SCC/环拒绝在模块粒度执行的既有优势显式成文。

- CLI 的 TTY 过程流只显示已提交的阶段、Slice、generation、验证、集成和交付事实，最多固定四项活动对象；`-q/-v/-vv` 只改变摘要粒度，绝不显示模型思维链、prompt、源码正文、完整日志或凭据。首次 Ctrl+C 以 `If-Match` 请求正常取消并等待 actor 确认，第二次只退出本地观察且明确取消是否已确认；非 TTY 的 JSON/JSONL 输出同样沿用脱敏和 sequence 语义；
- 本决策不改变 V3 的 11 个核心 crate、plugin wire v2、per-Slice candidate/worktree、三层验证、active-dispatch gate、默认 `app + sandbox-worker + PostgreSQL`、4 GiB/2 CPU/10 GiB 沙箱配额、并发公式或安全模型。

本轮实施完成 M-00 的文档导航和 owner 索引、M-01 的 CLI/Web 物理边界、M-02 的只读投影契约，以及 M-03、M-04、M-07、M-08、M-10、M-11、M-13、M-14 的直接消费链接。随后补充 CLI 默认 TTY 跟踪、`--no-follow/--follow`、`human/json/jsonl` 输出、事件压缩、Ctrl+C 的条件取消和脱敏出口。后续详细编码设计以 M-15 的模块、事件和可观察结果为准，不将其降格为视觉概念稿。

## D-029 · 2026-08-13 Slice 全链路并行与最小协调决策

本节取代 D-003 中“单机仍保留 CAS/租约/fencing/Outbox 等生产级协议”、D-023 中单一 `work/verified` 双 ref 主线，以及 D-025 中 Redis 可作为通知 profile 的旧协调边界。V3 不把“删掉分布式机制”理解成“删除所有竞争保护”，而是只保留与当前可观察竞态对应的窄机制。

触发本次重构的是 [fb1](../feedback_doc/fb1.md) 与 [fb2](../feedback_doc/fb2.md) 对 V2 过度协调的质疑。源码核验目录为 `temp/restored-src`，核验结果支持“单机不需要为未来水平扩展保留周期租约和全局 fencing”，但不支持反馈中的四个前提：

- `AgentTool.tsx` 只在 `effectiveIsolation === 'worktree'` 时创建 worktree，因此 worktree 是可选隔离而不是所有 agent 的物理事实；CodeMigrator 不能据此假定共享文件写入天然消失；
- Node.js 单事件循环只串行执行 JavaScript 片段，不能让跨 `await` 的读—改—写成为原子事务；源码中的 `proper-lockfile` 使用以及 Bash 写工具的保守 `isConcurrencySafe` 也表明产品没有把“单线程”等价成“无竞态”；
- `AbortController` 是协作取消，不撤销已经提交的文件、Git 或子进程副作用；`runAgent.ts` 仍显式调用 `killShellTasksForAgent` 清理孤儿 shell，远程桥接路径也存在 heartbeat/lease，因此“取消信号足以撤销全部副作用”不能作为 CodeMigrator 的安全前提；
- V2 当前正文只有 Run 级 `work` 与 `verified`，并没有反馈所假设的“每个 Slice 已有独立 work ref”。要获得真正的 Slice 并行，必须先新增每 Slice candidate ref、worktree 和上下文隔离，再讨论可以删除哪些协调机制。

基于上述核验，本轮接受反馈对“机制泛化过度”的判断，驳回“Git 隔离使全部协调都没有价值”和“PostgreSQL 可直接替换为文件系统”的结论。当前项目是可重启 REST/SSE 后台服务，不是交互式 CLI；它需要 API 幂等、条件取消、自动续跑、查询投影和事件断点回放。若使用 JSONL，仍需自研文件锁、原子追加、损坏尾截断、索引和单调事件序列，因此 PostgreSQL 保留为唯一控制面后端，纯文件系统只作架构对照。

- PostgreSQL 保存 Run、Slice、candidate generation、active dispatch、验证证据、integration intent/receipt、API 幂等键和 append-only `run_events`；Run 状态变化与事件在同一事务提交，SSE 按 `(run_id, sequence)` 回放，`LISTEN/NOTIFY` 只负责唤醒；
- Git 保存冻结 base、每 Slice candidate、integration scratch、唯一 verified 与 failed/abandoned 证据；host CAS 保存源码切片、模型/工具日志和报告正文；三者职责互不替代；
- `app` 以 PostgreSQL session advisory lock 保证单控制面写者，每个 Run 用内存 actor 串行处理控制命令；第二个 app 不 ready，持锁连接丢失时当前 app 停止接单并退出；
- 删除 30 秒 lease、20 秒续期、全链路 `fencing_token`、每步 expected-state/version CAS、Outbox relay 和轮询式 reconciler。保留 Git expected-OID ref transaction、外部取消 `If-Match`、数据库幂等唯一约束与 app session lock；
- 每次物理 worker 派发使用新的 UUIDv7 `DispatchAttemptId`；返回结果必须匹配 active attempt、`CandidateGeneration` 与 candidate OID。取消、断连或重派后的迟到结果只写审计事件，不形成 `CheckResult` 或 Git 推进；
- app 与独立 sandbox-worker 通过宿主可访问的类型化 Unix domain socket 协作，worker 不连接 PostgreSQL，bubblewrap 不挂载控制 socket。app 断连时 worker 清空全部沙箱进程组；5 秒内无法清空则自行退出，由 Compose 重启；
- Planner 为每个 Slice 冻结 `write_files`，默认来自 locator 路径，插件 rule descriptor 只能追加固定辅助路径；不可预知写路径的规则标记 `REPOSITORY_EXCLUSIVE`。写集合相交或任一方独占时生成确定性 `ordered_before`；运行期触及未声明文件返回 `WRITE_SET_VIOLATION`，不得动态扩权；
- 每个 Slice generation 使用 `refs/codemigrator/runs/<run_id>/slices/<slice_id>/candidates/<generation>`、独立 worktree、Artifact 命名空间和模型上下文。generation `0` 是初始候选，`1`、`2` 是从最新 verified 发起的两次语义重生成；物理重派只更换 DispatchAttempt，不消耗 generation；
- Integration Coordinator 按计划时冻结的“拓扑层升序、Slice 最高规则 priority 降序、SliceId 升序”严格消费。候选可并行生成和局部验证，完成速度不改变 verified commit 序列；后序候选可以继续计算，但不能越过正在重生成的队首集成；
- 验证固定为三层，并以判别联合 `VerificationSubject::LocalCandidate/ProspectiveIntegration/FinalVerified` 阻止层级字段混用；每个 outcome 分离语义 fingerprint 与 evidence identity：前者只覆盖 tested commit、冻结检查集和规范化结果语义，后者再绑定 subject、receipt、完整日志 ArtifactRef 等证据。最后两层只在同 commit/检查集的语义 fingerprint 不一致时返回 `NONDETERMINISTIC_VERIFICATION`；证据载体差异只改变 evidence identity；
- prospective Oracle 通过后必须先在单个 PostgreSQL 事务持久化 integration intent，完整冻结 expected/prospective OID、Slice、generation、guard/fingerprint 与幂等键；事务提交后才执行 Git expected-OID CAS，成功后再以单个事务写 receipt 与 `run_event`，恢复不得补造缺失 intent；
- RunStatus 不增加枚举。`EXECUTING` 覆盖候选生成、局部验证、集成排队、重生成与逐 Slice 集成，`VERIFYING` 只表示最终全局验证；主线由 V2 的双向 repair 改为 `EXECUTING → VERIFYING → REPORTING` 单向流。Slice 以独立细粒度状态投影进度；
- generation `2` 仍无法集成时固定返回 `SLICE_REGENERATION_EXHAUSTED`，failed ref 保留 30 天，并按 `IndependentSliceTerminalFailure` 判断是否允许部分完成。用户取消恒为 `CANCELLED`，已集成 Slice 只作为终态投影保留；
- Redis cache/wakeup profile 从当前实现矩阵删除；MinIO 镜像和观测 profiles 保持可选。11 个核心 crate、plugin wire v2、默认 `app + sandbox-worker + PostgreSQL`、4 GiB/2 CPU/10 GiB、并发公式和沙箱安全模型均不改变。

崩溃恢复改为事实驱动而非周期巡检。若 Git verified 已推进而 PostgreSQL receipt 缺失，启动 Recovery Coordinator 补写 receipt而不重复应用；若 intent 已写但 Git 未推进，则按 recorded expected OID 幂等重试。worker 断连立即触发 dispatch 接管，app 重启按非终态 Run 和 Git refs 重建 actor；checkpoint 只作可重建索引。Recovery Coordinator 由启动、断连或已知 intent 缺口触发，不作为常驻轮询 reconciler。

本轮已实施公共基线 [M-00](CodeMigrator_垂类设计原则与架构哲学.md)，并要求 [M-01](CodeMigrator_核心目录架构设计.md)～[M-14](CodeMigrator_记忆与上下文管理.md) 全部同步消费；其中 [M-04](CodeMigrator_Agent_Loop设计.md)、[M-05](CodeMigrator_Migration_Spec抽象层.md) 与 [M-06](CodeMigrator_代码分析与AST引擎.md) 分别落实 agent 提案边界、write scope 来源和 generation candidate 重定位。后续若要恢复多 app、远程 worker 或水平扩展，必须通过新的架构决策重新引入与故障模型匹配的协调协议，不能把 V2 已删除的机制以“预留”名义静默带回。

## D-028 · 2026-08-11 插件 Wire v2 与候选重定位闭环决策

本节取代 D-022 中“dispatch 恰为七个方法”的冻结表述，以及 V2-R-003 中 `host Locate/Parse/EmitPatch` 的旧候选路径。触发原因是：`NodeLocator` 的 `snapshot_oid` 只能证明 ANALYZE 来源，候选 commit 上的结构匹配必须由持有语言 AST 的插件完成；通用 host 既不能伪造语言级 Locate，也不能将 candidate Query 重新写成计划事实。

- 插件进程协议升级为 `api_version=2`，由 [M-01：工程边界与插件进程](CodeMigrator_核心目录架构设计.md) 唯一拥有；host→plugin dispatch 固定为八个方法：`Parse`、`Query`、`DependencyFacts`、`ResolveLocator`、`EmitPatch`、`BuildArgv`、`ParseDiagnostics`、`ReleaseParsedUnit`；
- `api_version=1` 在 CreateRun 事务前以 `CAPABILITY_INCOMPATIBLE` 拒绝，不产生 Run、outbox 或 Git 副作用；旧 wire 文本保留在归档区，仅作历史追溯，不能作为实现依据；
- EXECUTE 与 repair 的唯一候选链为：锁定 `CandidateCommit`，读取并保存 candidate blob，`Parse(candidate)`，`ResolveLocator(original locator)`，host 对同一 commit 的 match proof 做原子复核并读取 range，物化 canonical `ResolvedSourceSlice`，最后才向 `EmitPatch` 交接；
- `ResolveLocator` 返回的是 `ResolvedLocation` 与匹配证明，不产生新的 `NodeLocator`；`NodeLocator` 始终保留 snapshot 的来源身份，当前 range、当前内容 hash 与 work commit 只是 candidate 事实；
- 该变更不调整 11 crate、RunStatus、安全隔离、资源限制或默认部署边界。M-06、M-08、M-10、M-12、M-14 只消费这条路径；后续插件或 host 设计不得恢复 `Locate` 作为 host 操作或 wire 方法。

已实施波次：M-00 仅保留公共不变量与 owner 链接；M-01 发布 wire v2；M-05～M-10、M-12、M-14 完成候选路径同步。相关模块见 [M-01](CodeMigrator_核心目录架构设计.md)、[M-06](CodeMigrator_代码分析与AST引擎.md)、[M-08](CodeMigrator_候选工作区与工具网关.md)、[M-10](CodeMigrator_验证引擎.md)、[M-12](CodeMigrator_工具系统与Hook.md) 与 [M-14](CodeMigrator_记忆与上下文管理.md)。

### 原始技术术语、概念与背景

### 运行与调度
- **AgentRun**:一次 Agent 执行实例,从接收迁移请求到产出迁移报告
- **TaskPlan DAG**:迁移任务的有向无环图,节点为原子任务,边为依赖关系
- **Dispatch 租约**:任务分发时授予执行器的租约,带 fencing token 防止脑裂
- **Checkpoint**:Agent 运行状态的持久化快照,用于崩溃恢复

### 代码分析与迁移
- **Migration Spec**:声明一类迁移的规范(源语言、目标语言、AST 节点映射、验证策略)
- **AST 引擎**:基于 tree-sitter 的多语言语法树构建与查询
- **依赖图**:项目内文件/模块/符号之间的依赖关系图
- **迁移计划**:根据 Migration Spec 与项目分析结果生成的分阶段执行计划

### 数据与存储
- **PostgreSQL**:状态真相源(AgentRun、TaskPlan、Checkpoint、Migration Spec)
- **Redis Streams**:通知层(任务分发、事件流)
- **MinIO / 本地卷**:持久正文源(代码快照、构建产物、迁移报告)

### 沙箱与执行
- **bubblewrap**:轻量 Linux 命名空间隔离,用于 AST 解析等低风险操作
- **Firecracker microVM**(二期):AWS 微 VM,用于运行不可信代码的构建与测试
- **验证闭环**:修改→构建→测试→失败诊断→修复重试的循环
