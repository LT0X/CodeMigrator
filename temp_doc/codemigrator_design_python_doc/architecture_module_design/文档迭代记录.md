## 1. 首篇记录 · 2026-08-27：Rust V4 基线 → Python 版语言迁移（历史，非当前 V5 基线）

本节只记录 Python 版从 Rust V4 基线迁移时的历史决定；其中关于 V4 机械规划、三件输入和旧验收口径的描述不再定义当前契约。当前 V5 同步结果见第 2 节及各模块文档的 V5 当前对齐段。

### 1.1 迁移背景

本文档集原为 Rust 实现设计，随 V4 基线演进累积 374 行历史迭代记录（本篇即对其整体重置）。

现将实现语言切换为 Python，驱动有二：其一，设计须与实现同栈，方能直接指导 Python 版施工；其二，借这次完整的设计迁移沉淀 Python 工程能力（个人能力沉淀）。迁移原则：只替换实现语言词汇，不动架构语义——零新机制、零新工具、零新流程；V4 的可复算性承诺（同输入必同计划、fingerprint 确定性）与实现语言无关，迁移后继续成立。

### 1.2 迁移范围

- **17 篇模块设计文档**（M-00～M-16）：设计思想、模块编号、契约条款全部保留，仅实现语言词汇按统一映射表替换；
- **本迭代记录**：Rust 版历史条目（含各期演进记录、缺陷索引与历史材料归档）全部清空，以本篇为 Python 版首篇记录；Rust 版历史不再承载当前契约，如需追溯以仓库版本历史为准；
- **重置自检**：本文件不含任何 Rust 版历史迭代条目，也不复制映射决策表正文，避免产生第二份定义。

### 1.3 契约冻结声明

以下契约在迁移中保持不变，继续作为唯一真相源；后续任何修订均须走演进流程并记录于本文件：

- 模块编号 M-00～M-16 及各篇职责边界；
- 验收条款编号 `V-Mxx-V4-xxx` 全集及其语义；
- 冻结错误码体系；
- 全部状态机（主线状态机、会话生命周期、漂移修正回路等）；
- app 直接管理 bwrap 的执行边界与三池资源治理；
- 描述符摘要体系；
- 部署拓扑（`app + PostgreSQL` Compose 基线）。

条款正文分布于各篇模块设计文档，本记录只声明冻结口径，不复制条款内容。

### 1.4 语言映射决策

一句话概述：实现载体由 Rust Cargo workspace（8 个 crate）整体映射为 Python 3.12+ 单包 src-layout 8 个子包（uv 管理）；运行时与基础设施按固定对应关系替换——tokio→asyncio、axum→FastAPI、sqlx→SQLAlchemy 2.0+asyncpg、serde→Pydantic v2、trait→typing.Protocol、tree-sitter→py-tree-sitter、tracing→structlog+OpenTelemetry、cargo metadata→import-linter、bin target→`[project.scripts]` entry points、Cargo.toml→pyproject.toml。映射仅作用于实现层词汇，不影响任何验收条款的编号与语义。

完整 Rust→Python 映射决策表的**唯一 owner** 是 [M-01 核心目录与描述符资源架构](CodeMigrator_核心目录架构设计.md) 的「语言基线与映射决策」一节；本记录与其余各篇一律引用该节，不复制整表，以免产生第二份定义。
