# pr_md/ PR 说明规范

> 书写任何 PR 说明文档前先读本文件。PR 文档命名：`pr_md/CM-<模块缩写>-<序号>-<简述>.md`。

## 必含章节

1. **标题与关联**：PR 标题（与 commit/分支名一致）、关联任务编号（T-Bxxx）、关联模块迭代记录链接。
2. **背景**：为什么做（引用设计文档章节或验收条款编号，如 V-M07-V4-009）。
3. **变更点**：按 crate/目录分组的变更清单；标注 BREAKING 与对公共契约（M-00）的影响。
4. **自测证据**：编译/测试命令与结果；对照验收条款的勾选结论；在 Linux 虚拟机上完成的沙箱相关验证须注明环境。
5. **风险与回滚**：行为变化点、兼容性影响、回滚方式。

## 约束

- 不粘贴密钥、`.env` 内容、宿主机绝对路径中的敏感信息。
- 涉及设计文档语义变更的 PR，必须先完成 §3.4 设计文档同步再发起 PR。
- PR 描述与实际 diff 不符时，先修正再请求 review。
