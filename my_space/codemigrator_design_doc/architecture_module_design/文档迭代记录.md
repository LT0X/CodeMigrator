## 0. 文档集与基线速览

* **文档集构成**：M-00～M-16 共 17 篇模块设计文档（`CodeMigrator_*.md`，平铺于本目录）＋本迭代记录。

* **架构基线（V5）——核心形态**：跨语言代码迁移 Agent（源项目严格只读、全量翻译为目标语言新项目）；Harness 编排层 + Agent 直写六工具（ReadFile/WriteFile/EditFile/QuerySourceAst/Shell/Exec）；预索引知识图谱与域扇出探索；四件冻结工件；LLM Planner + 机器校验；三池资源模型。

* **架构基线（V5）——执行与验证**：Planner 可选 Contract Slice，依赖闭包就绪即启动；app 直接管理 bwrap；Slice 长期沙箱卷跨命令保留缓存；验证从 tested commit 临时物化目录执行；三层确定性 Oracle、Git/CAS、Spec 起草与契约漂移修正协议保留；CLI 主入口 + Web 只读工作台。

* **实现基线（设计待实施）**：Python 3.12+ 单包 src-layout、uv 管理、import-linter 层间依赖契约；部署拓扑为 `app + PostgreSQL` Compose 基线，独立 sandbox-worker/UDS/overlay 授权退场。

* **基线沿革**：V6 为当前设计文档基线；V5、V4、V3 与 V2 仅作追溯，不重新定义当前契约。

* **契约真相源**：公共领域类型与验证契约以 [M-00 垂类设计原则与架构哲学](CodeMigrator_垂类设计原则与架构哲学.md) 为准；子包组成与语言映射以 [M-01 核心目录与描述符资源架构](CodeMigrator_核心目录架构设计.md) 为唯一 owner。

* **架构基线（V6）——判断层新增**：在 V5 基线上新增**常驻主 Agent 判断层**（起草期探索协调者 + 执行期 EXECUTE Supervisor），只出建议（Advice）、决策权在 Harness 白名单收养；三级架构（权力层 Harness / 判断层常驻主 Agent / 执行层工作会话）；知识图谱构建前移；两级修复路由（重生升级包 + 全局修复会话）；探索后多轮 AskUser 对齐（全周期不限次）。V5 的确定性 Oracle、六工具、Git/CAS、三层验证与恢复语义保持。

## 1. 首篇记录 · 2026-08-27：Rust V4 基线 → Python 版语言迁移（历史，非当前 V5 基线）

本节只记录 Python 版从 Rust V4 基线迁移时的历史决定；其中关于 V4 机械规划、三件输入和旧验收口径的描述不再定义当前契约。当前 V5 同步结果见第 2 节及各模块文档的 V5 当前对齐段。

### 1.1 迁移背景

本文档集原为 Rust 实现设计，随 V4 基线演进累积 374 行历史迭代记录（本篇即对其整体重置）。

现将实现语言切换为 Python，驱动有二：其一，设计须与实现同栈，方能直接指导 Python 版施工；其二，借这次完整的设计迁移沉淀 Python 工程能力（个人能力沉淀）。迁移原则：只替换实现语言词汇，不动架构语义——零新机制、零新工具、零新流程；V4 的可复算性承诺（同输入必同计划、fingerprint 确定性）与实现语言无关，迁移后继续成立。

### 1.2 迁移范围

* **17 篇模块设计文档**（M-00～M-16）：设计思想、模块编号、契约条款全部保留，仅实现语言词汇按统一映射表替换；

* **本迭代记录**：Rust 版历史条目（含各期演进记录、缺陷索引与历史材料归档）全部清空，以本篇为 Python 版首篇记录；Rust 版历史不再承载当前契约，如需追溯以仓库版本历史为准；

* **重置自检**：本文件不含任何 Rust 版历史迭代条目，也不复制映射决策表正文，避免产生第二份定义。

### 1.3 契约冻结声明

以下契约在迁移中保持不变，继续作为唯一真相源；后续任何修订均须走演进流程并记录于本文件：

* 模块编号 M-00～M-16 及各篇职责边界；

* 验收条款编号 `V-Mxx-V4-xxx` 全集及其语义；

* 冻结错误码体系；

* 全部状态机（主线状态机、会话生命周期、漂移修正回路等）；

* app 直接管理 bwrap 的执行边界与三池资源治理；

* 描述符摘要体系；

* 部署拓扑（`app + PostgreSQL` Compose 基线）。

条款正文分布于各篇模块设计文档，本记录只声明冻结口径，不复制条款内容。

### 1.4 语言映射决策

一句话概述：实现载体由 Rust Cargo workspace（8 个 crate）整体映射为 Python 3.12+ 单包 src-layout 8 个子包（uv 管理）；运行时与基础设施按固定对应关系替换——tokio→asyncio、axum→FastAPI、sqlx→SQLAlchemy 2.0+asyncpg、serde→Pydantic v2、trait→typing.Protocol、tree-sitter→py-tree-sitter、tracing→structlog+OpenTelemetry、cargo metadata→import-linter、bin target→`[project.scripts]` entry points、Cargo.toml→pyproject.toml。映射仅作用于实现层词汇，不影响任何验收条款的编号与语义。

完整 Rust→Python 映射决策表的**唯一 owner** 是 [M-01 核心目录与描述符资源架构](CodeMigrator_核心目录架构设计.md) 的「语言基线与映射决策」一节；本记录与其余各篇一律引用该节，不复制整表，以免产生第二份定义。

## 2. V6 收敛同步记录 · 2026-08-28

本次依据 [fb11\_align\_records](../feedback_doc/fb11_align_records.md) 对 V6 文档基线做收敛优化（V6 收敛版，不另立大版本号），统一修订受影响文档，各文档头部标记为"V6 收敛版"，历史段留存追溯。

### 2.1 收敛背景

fb11 架构反馈对刚落地的 V6 提出三点收敛质疑（ANALYZE 阶段冗余、Supervisor 常驻模型多余、修复路由分界需按归因可靠性重划），经多轮 AskUser 与用户逐项对齐（9 决策点收敛，详见 fb11\_align\_records.md）。V6 收敛保留 V6 三层架构/判断层/修复机制的主体，仅收敛三处机制形态与一处阶段归属。

### 2.2 已落正文的收敛

* **ANALYZE 并入 CreateRun**（M-00/M-02/M-04/M-06/M-13/M-15/M-16）：五阶段→四阶段（RunStatus 删 ANALYZING，CREATED→PLANNING 直连）；ANALYZE 三件事（复用投影/冻结校验/档案一致性）并入 CreateRun 为断言分支，档案一致性断言失败返回 `DOSSIER_INCONSISTENT` 零副作用拒绝（fail-fast）；Phase 授权表删 ANALYZE 行；M-13 phase 标签 5→4、series 上限 287→251；M-15 阶段条四阶段。

* **Supervisor 去常驻**（M-00/M-03/M-04/M-12/M-13/M-14/M-15）：删除"被动唤醒式常驻+滚动摘要"机制；Supervisor 改*事件触发式新会话*，每次触发由统一 Context Manager 定向装配；M-14 从"Slice 会话预算治理"升级为"全类型会话统一上下文基建"。探索协调者（起草主会话）是交互式会话天然贯穿，走标准 M-14 机制。

* **修复路由收敛为"可靠域直通+其余统一 Supervisor"**（M-00 P-09/M-07/M-10）：分界=归因可靠性——静态诊断唯一命中（零推测）走原 Slice 重生直通；静态多命中+全部动态测试失败（推测性归因）统一唤醒 Supervisor 决策；机械归因从"路由判据"降级为 Supervisor 输入证据；修复重试上限与 Run 终态边界（全局修复耗尽才终态）。

* **新增**：三段式 KV-cache 前缀架构（稳定前缀/演进段/定向增量，M-04/M-14）、静态会话模板库（M-04/M-12）、`FailureReason.DossierInconsistent`（M-00）。

### 2.3 仍开放的 V6 收敛实施细节

严格沿用 fb11\_align\_records §5：档案一致性断言的"重大偏差"判定阈值、修复重试上限数值、静态会话模板库资源形态、演进段字节稳定性保证、KV-cache provider 适配差异、可靠域直通"静态唯一命中"精确判定（lint 噪音过滤），及各文档 V6 验收条款的对应改写。本次不把这些开放项写成代码事实。

## 3. V6 文档同步记录 · 2026-08-28

本次依据 [fb10\_align\_records](../feedback_doc/fb10_align_records.md) 将 M-00～M-16 全部 Python 架构篇同步到 V6 方向，各文档头部标记为"V6 方向对齐版"，V5 对齐段与 V4 验收段留存为追溯。

### 3.1 背景与动机

fb10 架构反馈对 V5 提出三点质疑（扇出探索协调机制、知识图谱构建时序、跨 Slice 返工归属），经由多轮 AskUser 与用户逐项对齐（11 个决策点收敛，详细见 fb10\_align\_records.md），确立四类 V6 方向性决策。V6 保留 V5 的确定性 Oracle、六工具、Git/CAS 单写者、三层验证与恢复语义，仅新增判断层协调与修复路由。

### 3.2 已落正文的变化

* **三层架构与常驻主 Agent 判断层**（M-00 公共契约 + M-03/M-04/M-12）：权力层 Harness / 判断层常驻主 Agent（起草期探索协调者 + 执行期 EXECUTE Supervisor）/ 执行层工作会话；只出 Advice、零直写权、actor 白名单两级收养（约束内自动收养 / 边界性转确认门）；增益层优雅降级（判断层缺席退回机械路径）。

* **知识图谱构建前移**（M-06 + M-00）：首次构建前移至项目注册/起草会话开启，键 = snapshot OID + 描述符摘要，三期共用；ANALYZE 职责重定义为复用 + 冻结校验 + 档案一致性校验。

* **两级修复路由**（M-10/M-07/M-12/M-14 + M-00 P-09）：归因输出升级为候选修复集；简单场景原 Slice 重生升级包（全境读 + 修复简报）；复杂场景（多义/守恒后仍多义/跨代复发/强耦合）升级 Supervisor 派发全局修复会话（联合域条件化例外，不占 generation 0-2），免 ImpactPreview 确认门；"仍多义→Run 终态"改为"升级 Supervisor → 全局修复先试 → 才终态"。

* **起草流程与 AskUser 纪律**（M-16）：探索完成→归并→多轮 AskUser 对齐→工件草稿→确认冻结；取消"一次最多三题"框架限制（全周期不限次、agent 自主判断）。

* **联动适配**（M-01/M-02/M-13/M-15）：子包职责含常驻会话归属；run\_events 事件集新增 advice/修复决策/修复会话事件；观测适配；Web 全局修复会话 persona 与 Supervisor 决策视图。

### 3.3 仍开放的 V6 实施细节

严格沿用 fb10\_align\_records §6：Advice 白名单精确枚举、联合域安全判定算法、修复简报/态势快照/滚动摘要 schema、常驻会话预算数值、探索协调者 focus brief 模板与校验项、各文档验收条款的 V6 改写、M-15 Web 详细设计。本次不把这些开放项写成代码事实。
