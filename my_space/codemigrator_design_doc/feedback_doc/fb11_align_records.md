## 1. 议题一：ANALYZE 阶段去留

### 1.1 fb11 矛盾定位

V6 已把 tree-sitter 解析前移至项目注册/起草会话开启，ANALYZE 只剩三件轻量事：复用投影（运行时装载，非计算）、冻结校验（投影摘要==Spec 锁定摘要，纯断言）、档案一致性校验（Dossier vs 机械事实，一次比对）。用户质疑：只剩断言的阶段单独列为一个 RunStatus 阶段（ANALYZING）+ 一次状态转移是否冗余。

### 1.2 对齐分析

剩余职责与 CreateRun 的关系审视：

| 剩余职责    | 本质       | 与 CreateRun 关系                                                            |
| ------- | -------- | ------------------------------------------------------------------------- |
| 复用投影    | 数据访问，无计算 | 非阶段职责                                                                     |
| 冻结校验    | 一次断言     | 与能力门预检几乎重叠（CreateRun 已校验描述符/grammar/镜像摘要；投影键=snapshot OID+描述符摘要，等价断言投影存在） |
| 档案一致性校验 | 一次比对     | CreateRun 前置条件的自然延伸，有防御意义但无需独立阶段                                          |

影响面核查：RunStatus 删 ANALYZING（CREATED→PLANNING 直连）、P-06 五阶段→四阶段（Reasoning 档只剩 PLAN）、M-04 阶段表删行、M-06 产出归属改"预索引+CreateRun 校验"、M-02 首事件序列、M-13 phase\_duration 标签 5→4、M-15 阶段条显示——全部机械性修订，无语义障碍。

### 1.3 决策

* **主决策（方案 A）**：合并入 CreateRun。五阶段变四阶段（CREATED→PLANNING→EXECUTING→VERIFYING→REPORTING）。ANALYZE 三件事并入 CreateRun：冻结校验与能力门预检同点（断言投影存在+摘要一致）；档案一致性校验作为 CreateRun 完成前的最后断言。

* **偏差处置**：档案一致性校验=CreateRun 内**普通断言分支**——正常零感知；不一致则错误码（如 `DOSSIER_INCONSISTENT`）零副作用拒绝，无分档无特殊流程。用户判断依据：个人项目场景下档案与机械事实不一致极少出现（快照注册时已冻结、档案基于同一投影确认），极少发生的事只值一个 if 分支的机制成本，但也不放带缺陷输入的 Run 白烧后续预算（fail-fast）。

* **失败语义**：`AnalysisFailed` 语义保留为 CreateRun 拒绝码家族成员（原 ANALYZING→FAILED 转移随阶段删除）。

## 2. 议题二：Supervisor 常驻模型去留与上下文管理统一

### 2.1 fb11 矛盾定位

fb10 定的"被动唤醒式常驻"=会话跨触发连续+滚动摘要机制（近期详情+远期蒸馏+有界窗口）。fb11 质疑：既然都是主动触发，每次唤醒前组织好必要上下文即可，何必维护常驻会话与滚动摘要这套特有机制？且上下文压缩应全系统统一、代码复用。

### 2.2 对齐分析

四点关键洞察：

1. **修复决策不是连续对话**——每次决策自带完整证据（失败现场+候选修复集+调用链+期望vs实际），不依赖上次决策"记忆"。滚动摘要维护的会话连续性收益存疑，成本（滚动窗口状态/失效语义/蒸馏规则/重建语义）实付。
2. **去常驻与 KV-cache 前缀复用天然契合**——provider 的 prefix cache 不要求会话常驻，只要求每次请求前缀字节稳定（议题三 3b 落地）。
3. **统一上下文管理**：M-14 已有完整机制（定向装配/水位逐出/不可逐出集合/CAS 外置/精确计数），Supervisor 唤醒装配直接复用同一代码路径，删除"滚动摘要"会话类型特例。
4. **探索协调者不受影响**：起草主会话是交互式会话（用户多轮对话+AskUser），天然一次会话贯穿起草全程——本来就是"常驻"的（交互需要），标准 M-14 机制管理即可，无需特殊化。

### 2.3 决策（方案 A：去常驻+统一基建）

* **去常驻**：Supervisor 每次触发=新会话；删除"滚动摘要"特有机制；唤醒时定向装配（态势快照+本次决策相关事件投影）。

* **统一基建**：全类型会话（交互式起草会话/工作 Slice 会话/协调 Supervisor 会话/修复会话）共用**同一套 Context Manager**（装配、水位逐出、不可逐出集合、CAS 外置、精确计数）——M-14 从"Slice 会话的预算治理"扩展为"全类型会话统一上下文基建"；删除会话类型特有机制，会话差异只体现在**装配模板与预算档**。

* **上下文压缩统一确认**（对齐中用户追问）：压缩代码只有一份；水位逐出/不可逐出集合/大对象外置/精确计数对全部会话类型同一实现，会话类型只是配置档位。交叉约束：逐出只作用于定向增量段内旧轮次工具结果；稳定前缀段+演进段纳入不可逐出集合保护——长会话逐出不破坏前缀字节稳定性（KV-cache 命中不受逐出影响）。

* fb10 修订点：三层架构保留（判断层仍是 Supervisor/探索协调者角色），但"被动唤醒式常驻+滚动摘要"表述删除，改为"事件触发式新会话+统一装配"。

## 3. 议题三：修复路由统一、Supervisor 上下文构建、并行冲突

### 3.1 fb11 矛盾定位

三点：①集成测试和最终测试建议全部统一 Supervisor 处理（运行期 bug 如数值不符预期可能不报错，很难定义属于哪个 Slice）；②Supervisor 上下文要符合 KV-cache 前缀（动态维护，集成一个 Slice 从上一次更新增量追加，新来的 Slice 怎么高效给上下文）；③全局修复完成后是否可能影响并行在途 Slice 的集成（代码冲突）。

### 3.2 归因可靠性分析（对齐中确立的真正分界线）

| 错误类别                 | 归因方式                       | 可靠性                             | 适合路径                |
| -------------------- | -------------------------- | ------------------------------- | ------------------- |
| 静态诊断（编译/lint/类型）唯一命中 | file:line → write scope 查表 | **机械可靠，零推测**（错误位置就是证据本身）        | 直通重生（省一次调用）         |
| 静态诊断多命中 / 一切动态测试失败   | 证据推测（栈+调用链+守恒）             | **不可靠**（栈落点≠错误根源：根因可能在传参方而非计算方） | 必须 Supervisor 看整体现场 |

关键澄清（用户两次追问收敛）：动态运行错误（如 `test_order_total 期望 100.5 实际 100.49999`，不抛异常纯数值偏差）的归因本质是推测——栈落点在 A 的计算处但根因可能在 C 的传参转换。这类失败单 Slice 还是多 Slice 无法预先机械判定，必须模型看整体现场。

### 3.3 决策 3a：可靠域直通+其余统一 Supervisor（方案 B）

```
验证失败（集成层/最终层）
  → 机械归因（file:line→write scope 查表）输出候选修复集 + 归因可靠性分类
  ├─ 静态诊断唯一命中（机械可靠窄域）→ 直通：原 Slice 重生（占其 generation 0-2，带升级包）
  │   1 次模型调用；零新机制（V5 重生复用）
  └─ 其余一切（静态多命中 + 全部动态测试失败）→ 统一唤醒 Supervisor
      Supervisor 消费证据（候选修复集为参考输入）→ 修复决策 Advice：
        repair_set + 执行形态二选一：
          ① 单 Slice 委派重生（证据明确指向单 Slice 时）
          ② 全局修复会话（多 Slice 耦合时，联合域，不占 generation）
        + 修复简报
      → actor 白名单收养 → 派发
      2 次模型调用；归因不可靠问题被消解（归因只是证据不是裁决）
```

* 路由边界由系统机械判定（静态诊断+唯一命中），非用户/模型心智负担。

* 机械归因从 fb10 的"路由判据"**降级为 Supervisor 的输入证据**（候选修复集作为决策参考）。

* 集成期高频的接口不一致（静态诊断）不过 Supervisor——省调用省延迟；动态失败（归因不可靠）必有 Supervisor 整体视野。

### 3.4 会话创建机制澄清（对齐中两次追问定案）

**本架构无子 agent 工具——任何模型都不能 spawn 模型**（P-01 冻结：六工具、无扩展注册）。

```
① actor 唤醒 Supervisor（编排动作，非工具调用）：
   Context Manager 统一装配会话——角色系统提示←Harness 静态会话模板库（版本化受信资源）；
   冻结工件引用+Run 级固定事实+verified 演进摘要←确定性代码从审计事实派生；
   定向增量：本次失败证据←机械提取。actor 以 Reasoning 档开启会话（零写权/只读）
② Supervisor 出 RepairDecision（结构化输出经归一器收敛）→ actor 邮箱
③ actor 白名单校验收养（repair_set 合法性+联合域安全条件）
④ actor 派发全局修复会话（与派发普通 Slice 会话同一套编排机制）：
   角色系统提示←同一模板库的修复会话模板；修复简报←Supervisor 决策（唯一模型产出段，
   经归一+actor 校验）；导航索引←repair_set write scope 与失败证据机械派生；
   actor 冻结联合域 write scope、开沙箱卷、Code 档派发
```

**提示词准备的精确分工**：角色系统提示=Harness 静态会话模板库（版本化受信资源，与 phase policy 同类管理）；上下文内容段=Context Manager 确定性装配+Supervisor 决策注入的修复简报（唯一模型产出，经归一器+actor 校验）。**任何模型（含 Supervisor 自己）都不准备其他会话的提示词**——派发权与装配权都在 actor（三层架构：权力层装配派发、判断层只出决策内容、执行层消费 pack 开工）。

### 3.5 决策 3b：三段式 KV-cache 前缀架构+统一装配器

```
[稳定前缀段] 角色系统提示 + 冻结工件引用（Spec/Dossier/Blueprint/Rulebook hash）+ Run 级固定事实
             ——字节跨调用不变 → provider prefix cache 命中
[演进段]     verified 演进摘要——每集成一个 Slice 只在段尾增量追加（动态维护，只动尾部最大化缓存命中）
[定向增量段] 本次失败证据：候选修复集+失败测试全文+相关调用链+期望vs实际——每次不同
```

* 装配器由 Context Manager 统一承载，所有会话类型（Supervisor/修复会话/重生会话）同一套前缀维护代码。

* "新来的 Slice 怎么高效给上下文"→它集成时只在演进段尾部追加自己的摘要条目，历史段零变动。

* 逐出与前缀稳定性的交叉约束：逐出只作用于定向增量段内旧轮次；前缀段+演进段受不可逐出集合保护（见议题二）。

### 3.6 决策 3c：并行冲突安全语义（验证链兜底）

**文件级冲突：结构性不可能**。计划冻结时 PlanValidation 保证全部 Slice write scope 两两互斥；全局修复联合域=修复集 scope 并集，与在途 Slice scope 计划期即不相交；Git 集成是输出文件集直接应用（非 merge）——修复写入路径与在途 Slice 输出路径零重叠。

**语义级冲突：可能发生，由验证链逐层兜底收敛**：

```
Supervisor 修复 A → verified 前推（B/D 仍并行跑各自工作区，互不干扰）
B 完成 → checkpoint → 排队集成 → 面对新 verified（含修复后 A）
  集成增量验证（编译+类型+已集成测试）：
  ├─ A 签名变了 → 类型检查立即报错 → 修复流程
  ├─ A 行为变了签名没变 → B 集成测试覆盖则暴露；未覆盖则
  └─ 最终验证（全套测试）兜底暴露 → 修复流程
```

**不设修复窗口冻结机制**：verified 单写者（Integration Coordinator 串行），在途 Slice 完成时排队、集成时面对当时最新 verified；修复不通知不阻塞任何并行 Slice——冲突在集成时刻由确定性验证自然裁决。这是"用数据结构协商，不用消息协商"哲学的延伸：修复改变共享不可变事实（verified），不发消息给 B。

### 3.7 决策 3d：修复会话集成序、基线时点、循环上限

* **集成序**：全局修复会话完成 checkpoint 后按 FIFO 入 Coordinator 串行队列（与普通 Slice 同队），不优先插队（保持冻结集成序纯粹性）。

* **verified 基线时点**：prospective 建立在**集成时最新 verified** 上（互斥写集保证触发时与集成时取基线均安全）。

* **修复循环上限**：修复决策层级设独立重试上限（与 generation 0-2 同构，数值实施期定）；每次修复由新证据驱动；Run 级预算断路器兜底。防"A/C 修好→B 集成又暴露→再修→…"无限循环。
