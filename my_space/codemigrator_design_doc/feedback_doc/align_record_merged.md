## 2. 议题一：并发架构与安全策略——子 agent 工具定案

### 2.1 一手核查结论（回应"他们能做到 agent 并发这么多且安全，我们为什么这么多限制"）

**结论 A｜真实并发数祛魅**："数百 agent"是全程累计实例数，不是同时并发：

| 案例 | 同时并发出 | 全程累计 | 一手出处 |
|---|---|---|---|
| Mike Krieger Python→165K 行 TS | **12 个子代理扇出**（Sonnet 档做实现，大模型留评审/规则） | "数百 agents"=8 相位门×每门多角色×多轮 | 博客正文 Step 3 |
| Jarred Bun Zig→Rust 百万行 | **峰值 64 实例 = 4 worktree × 16 循环**（原文 "About 64 Claudes at a time"） | ~50 个 dynamic workflow / 11 天 / 6,502 commits / $165K | Jarred 博客 Stats 节 |
| 本库 MVP 实测 | max-parallel=3，有效并发系数 2.207 | 单 Run 13 段会话 | runs_stats.json |

真实差距约 **4~20 倍**而非"数百 vs 个位数"。且 kit README 明言 *"The process works at any rate limit — the calendar doesn't"*——并发量级首先受 provider 配额约束；MVP 实测瓶颈第一位是端点健康（LLM_HTTP_503 报废两 Run、p50=12,665ms），第二位才是旧资源公式捆一池（已由 D-040 三池模型解除）。

**结论 B｜他们的安全=四层机制，全是本库已有能力的脚本版**：

| 博客机制（一手证据） | 本库对应物 | 对比 |
|---|---|---|
| 机械队列：done=输出文件在盘上，队列每次从盘重建，停止免费、恢复=重新调用 | candidate ref + checkpoint + Git refs 投影 | 更强（OID 内容寻址 CAS） |
| 配置化禁令：settings.json denies 禁 git stash/reset、禁 cargo、禁慢命令；prompt 校验存在性缺失即停 | write scope 白名单 + 裁决层唯一冻结通道 | 更强（构造拒绝 vs 请求式纪律） |
| 物理隔离：git worktree ×4 + systemd-run cgroups/pid namespace（机器仍崩数次） | bwrap 沙箱 + 候选工作区单卷 | 更强且免全仓克隆 |
| 裁判串行化：build daemon 独占重建权、fixers 无编译器访问权 | InternalVerificationDispatch + invocation_hash | 同构 |
| 反作弊规则：拒绝 stub 凑编译、"需要一段注释自圆其说的代码就是错的" | LOW_QUALITY 门槛 + Oracle 门 UNKNOWN=0 | 同构（见 G-15 提级） |

Jarred 的 agent 曾真实跑出 `git stash`/`git reset --hard` 互踩事故——该故障类在本库架构中不可能发生（会话不持 git 权限）。**定性：我们不是"限制多"，而是把他们靠 prompt+人盯的请求式纪律升级为构造式保证。**

**结论 C｜依赖地图实录核验**（fb8 旧问⑤的再验证）：kit README 自证 *"these prompts are reconstructions…not transcripts"*；Bun 实际 = 576 行 PORTING.md（约 3 小时对话由 Claude 序列化）+ 一句话 kickoff；LIFETIMES.tsv 生产链路 = 动态工作流逐 struct 字段追踪控制流 → 提案 → 2 对抗评审 → 应用 → 序列化成表供其他 claudes 消费——**与 MigrationRulebook 受控追加同构（D-039 判断被一手证据确认）**；循环依赖真实路径 = 手工 crate 拆分 PR 不彻底 → 工作流分类归属写下来 → 重构工作流 → cargo check 揭示 ~16,000 错误 → Phase D 64 路修复。kit depmap prompt 要求文件级 AND 目标分包级双粒度查环正是 Bun 踩坑的提炼，反证本库 SCC/环拒绝在模块粒度执行的既有优势。

**结论 D｜Claude Code 自身的扇出形态**：Task/Agent 工具与 dynamic workflows（JS 编排脚本 spawn 子代理，可 per-agent 选模型/per-subagent 选 worktree）都由 **harness 层**掌握；两篇博客中每个 implementer/reviewer/fixer 均为外层编排脚本直接派生的独立会话，**无一例会话内部嵌套派生**。dynamic workflows 博客自述单上下文长任务三大失败模式：agentic laziness / self-preferential bias / goal drift——其解法（独立上下文子代理 + 外部编排）与本库 P-01"Agent 直写、Harness 编排"同向。

### 2.2 定案（用户拍板）

1. **不加子 agent 工具**，扇出权维持 Harness 独占：博客所有并发均为 harness 外层扇出的实证 + 三大失败模式恰是 P-01 收编编排权的机制化理由 + 新增并发需求（审计抽样评审、规则条目提案）已由 D-040 三池模型与 M-06/M-10 运营闭环承载，零新增治理面（预算/事件归属/write scope 继承均不变）。
2. **安全架构四件套不动**（write scope diff 校验 / expected-OID CAS+冻结集成序 / bwrap 只罩不可信执行 / 裁决层唯一冻结通道），但两项实施提级（→G-15/G-16）。
3. **并发架构维持 D-040 三池模型**，新增一条粒度引导挂账（→G-13）：Slice 是并发单元，分组粒度无质量约束可能导致大项目扇出不足，需在理解会话/计划器成文"分组粒度与并行度目标挂钩"指导。

### 3.1 博客导航体系拆解（回应用户追问"轻量如何做到有效、兜底是什么"）

| 层 | 博客做法（一手证据） | 兜底 |
|---|---|---|
| 前置期地图 | kit depmap 三脚本全是文本级解析（import/include/build file 正则匹配），零类型解析零符号绑定；脚本内算拓扑序+SCC，收缩到分包粒度再查环 | ①先试 5 文件人工核对再全量；②双怀疑派审计（随机半不相交+对抗指派半、file:line 证据行、双向 diff、修脚本不修结果、换样重抽、三轮失败升级人）；③kit README："the dogfood map and inventory catches came from adversarial review, not first drafts" |

### 3.1b 导航图（dependency map）在原文中的角色解剖（用户追问补充）

**定位**：Step 1 三件奠基工件之一（Rulebook × Dependency Map × Gap Inventory），总览图将其划入共享文档区并一行定义："Dependency map *(the work, in order)*｜Rulebook *(read before every task)*｜Gap inventory *(for other Claudes to read)*"。原文赋予四大职能：

| # | 职能 | 原文依据 |
|---|---|---|
| 1 | 并行切分依据：知道哪些文件先迁、哪些必须同批 | Step 1 · Dependency map 段首句 |
| 2 | 工作队列唯一源头：拓扑序经 make_manifest.py 生成 manifest.tsv → Step 3 机械队列；done=盘上有文件→天然可恢复 | kit README Step 1/3 |
| 3 | 双粒度环探测器：文件级 SCC（环=整批迁移）＋收缩到目标 crate/package 边界再查一遍——"干净的文件图不代表干净的分区，编译器强制的是分区这一层" | kit README + prompt01 |
| 4 | 人签核门呈递物：计数＋双粒度环清单＋文件路径，"签核前下游什么都不许建"；另经 Prerequisites 声明它同时 feed 规则手册的分包地图 | prompt01 |

**生产契约**：禁令先行——"不要让 agent 读文件报告 import，每次跑结果都不同，非确定性工件不可验证"；故为确定性脚本（每边一行、只收仓内边、试 5 文件人工核对、保持快因会被反复重跑、序与 SCC 都在脚本内算）＋审计闭环（双怀疑派各抽 20 文件［随机不相交半＋对抗指派半］、file:line 证据行、双向 diff、确认差异=修脚本不修结果→整图重生成换样重抽、三轮失败或同类复发升级人）。深意：**不被信任的是地图本体，被信任的是"生产+审计流程"**（kit README 自认 catches 来自对抗评审而非初稿）。

### 3.1c 地图产生方式实录核验：三方交叉证据链（fb8 旧问⑤最终收口）

**结论：用户怀疑成立。** claude.com 博客描述的"确定性脚本产地图"是对方法论的重构提炼，非实录；Bun 案例中承担地图职能的是 Jarred 复盘博客里的小任务与手工操作：

| 证据方 | 内容 |
|---|---|
| 博客自证 ×2 | "The starter kit is a generalized template of the process above — **it's not what these specific ports ran on**."（六步法开篇＋Related 区两次出现）；总览图措辞为"This **mostly** follows Jarred's methodology" |
| kit README 出处块 | "these prompts are **reconstructions**…**not transcripts**. The real artifacts were messier: the Bun port's 'prompt' was a 576-line rulebook (PORTING.md，附 oven-sh/bun commit 46d3bc29 真实链接) and a **one-sentence kickoff**" |
| Jarred 实录全文核查 | 前置期仅 PORTING.md＋LIFETIMES.tsv＋联合评审＋3 文件试译，**无任何地图产物**；分包结构=重写前**手工 PR** 且自认 insufficient；循环依赖=**事后反应式两个小工作流**（分类归属写下来→重构）；事实上的排序装置=cargo check ~16,000 错误按 crate 分组的错误清单（裁判输出当队列） |

**方法论与实录须分开评分**：方法本身真实可用——kit 附三个可运行脚本＋fixtures 标准答案（expected_edges/cycles/order）＋RUN-NOTES 测试回执；决定性反证是 README 原句 *"Bun's port had a **clean file graph** and still hit ~16K compile errors from package-level cycles nobody had checked"*——若 Bun 真跑过双粒度查环脚本就不会"没人查过"，此句本身即证明其未用此法。

### 3.2 定案（用户拍板）

**维持 D-038 选型边界不动**：tree-sitter CST 只读采用 + PSF-2 符号索引 + 不引入原生 AST/LSP 引擎。依据：博客实践证明"轻导航+强裁判"成立而本库是"中等导航+强裁判"两头不吃亏；AST 深层语义增益已由语义消解层（理解会话+UnderstandingDossier）承接。同时：
- 两处**实现欠账记账**（详细编码设计重启时的既定要求，非架构变更）：QuerySourceAst 接 PSF-2 符号索引（设计本意，MVP 实况为文件文本读取）；守恒统计正则→tree-sitter（契约 B 原文口径，MVP 实况为正则计数）。

## 4. MVP 反馈 → 当前设计的逐域对齐结论

> 阅读指引：以下每域按"当前设计现状 → 实战证据 → 结论"组织。结论标记：✅ 维持不动｜🔧 修订候选（G 编号，最终形态见第 5 节 E 编辑点表）｜📌 实施提级（编码阶段必做）｜🗃️ 开放项。证据引用格式：（证：反馈文档条目/反思文档章节/一手博客位置）。

### 4.1 并发与执行架构
- 现状：三池模型（模型会话池数十路可扇出 / bwrap 沙箱执行位公式 / 裁决 active-attempt gate）。
- 证据：峰值并发实测受 max-parallel=3 限制下有效系数 2.207；五根因之④⑤均指向端点健康而非架构；检查进程耗时占比实测 0.27%~0.47%，时间主体是 LLM 往返（证：feedback X.3/X.6/X.7）。
- 结论：✅ 三池方向被博客一手数据支持；🔧 G-13 分组粒度引导；子 agent 工具不加（§2.2）。

### 4.2 安全机制
- 现状：write scope 双轨防护、expected-OID CAS、冻结集成键、bwrap、裁决唯一通道。
- 证据：MVP 全程 WRITE_SCOPE_VIOLATION=0、CAS 分叉异常零次、intents 链无分叉（证：反思第三部分#1/#2）；博客侧互踩事故反证其必要性。
- 结论：✅ 全部维持；📌 G-15/G-16 两项提级（作弊与检查集走样双方都有实录）。

### 4.3 动作协议与会话效率
- 现状：M-04 会话循环与 M-12 工具协议**均未定义"模型↔Harness 动作编码"层**；单轮单动作隐含假设未被任何条款挑战。
- 证据：单 JSON 协议转义必败史实（A-03，两代 0 次 write→整 Run 报废）；[cm:*] 标记分段协议一次通过并全程稳定；一轮一动作一往返是最大耗时结构因（65 往返 × p50 12.7s，证：feedback 根因①）。
